# pstack Pt. 2 — supervise someone smarter than you

Source (public): [@poteto X Article — The Complete Guide to pstack Pt. 2](https://x.com/i/article/2094940651607715840) · tweet [2097732320606507506](https://x.com/poteto/status/2097732320606507506) · Part 1 [verification](https://x.com/poteto/status/2094457600259842065).

This recipe **encodes the patterns**; install skills from [pstack](https://github.com/cursor/plugins/tree/main/pstack). Complementary notes — **not** a second factory OS and **not** Autopilot unlock.

## When to invoke

> Restate first — indirect prompt.
> Architect + prototype before the wave.
> Use pstack Pt. 2 supervise flow.

| Use | Skip |
|-----|------|
| Ambiguous Slack / user bug with noisy context | Typo / one-liner / already-specified Feature Map slice |
| New service boundary / API shape with open questions | Always-on every Cloud Agent spawn |
| Multi-PR migration that must stay visually identical | Replacing Riddler proof or Stewie gates |
| Teaching / grounding before you trust a plan | Greening TRUST-NEXT / overnight fleet |

## Failure modes

1. Under / poorly specified intent
2. Not enough context on how to do the work correctly

Prime high-quality context — do not micromanage frontier models line-by-line.

## Steal (encode these)

| Pattern | What it is | Where it lands | When |
|---------|------------|----------------|------|
| Indirect prompt | Agent restates problem in its own words before code | Harvey/Tony spawn briefs | Noisy intake |
| Supervise, don't micromanage | Outcomes + constraints; open solution space | Done means + Keep | Default |
| `/teach` → `/how` + `/why` | Explain; runtime; motivation across history | Product chats; Riddler | Before trusting a design |
| `/recall` | Multi-conversation context | Long threads | Spanning chats |
| Measure ×100, cut once | Investigate + prototypes before big cuts | Prototype playbook | Risky refactors |
| `/architect` + prototype | Shape; answer open questions empirically | Tony before multi-unit waves | New boundaries |
| Small verifiable PRs | Independent units + visual/live verify | Feature Map slices | Migrations |
| Plans as illusion | Prefer investigation + verify over abstract plans | `/poteto-mode` + evidence | Plan-forever temptation |
